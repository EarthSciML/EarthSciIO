EarthSciIO v0.2.0 ships two RFCs from EarthSciIntegrator in all three tracks
(Rust, Python, Julia). See [`CHANGELOG.md`](https://github.com/EarthSciML/EarthSciIO/blob/v0.2.0/CHANGELOG.md#v020)
for the full list.

- **Streaming Zarr v3 writer (RFC U12, #9):** shard-aligned region writes, so
  each rank writes its block of one array without a gather or a lock; commit
  tokens checked by one owner before the manifest is written; indexed
  (any-order) records with `invalidate`; statics, rank-local blobs, `uint8`, a
  read-back API and `resume` after preemption. The contract is
  [`spec/writer.md`](https://github.com/EarthSciML/EarthSciIO/blob/v0.2.0/spec/writer.md).
  New stores write `earthsciio/output-manifest/v2`; a single-writer,
  append-only store without statics still writes v1.
- **Epoch prefetch and named-dimension windows (RFC U11, #8):** `sample_at`,
  `DimWindow` / named `select` windows, `with_window`, `sample_windows_at`, and
  `PrefetchGroup`, which decodes upcoming forcing epochs on background workers
  bitwise identically to `sample_at`. The contract is
  [`spec/prefetch.md`](https://github.com/EarthSciML/EarthSciIO/blob/v0.2.0/spec/prefetch.md).
  The cache format stays `v1`.

### Breaking changes

- **Rust:** a time coordinate in `coords` passed to the Zarr writer must now
  hold exactly `dims[time_dim]` strictly increasing, non-NaN values
  (`spec/writer.md` §6.1). This is checked before any I/O; previously any values
  were written verbatim.
- **Python:** `ZarrWriter.write_record` now requires strictly increasing `t`,
  as the Julia and Rust writers do. `write_flush` returns a `CommitToken`.
- **Julia:** a single writer now commits (bumps `shape[time]` and rewrites the
  manifest) at `write_flush!` and `write_close!` rather than each time a time
  shard fills. A DISCRETE provider without a `time_dim` resolves its URL at the
  tick in effect, so `t` before the first tick raises `ArgumentError`.
- **Rust:** the order of inner chunks inside a shard object written by
  `write_zarr_v3` may differ from v0.1.4; the decoded arrays do not.
