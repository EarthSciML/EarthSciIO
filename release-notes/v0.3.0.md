EarthSciIO v0.3.0 lets every track (Rust, Python, Julia) build a data source
straight from an esm file's `data_sources` entry, and read it the same way. The
contract is the new
[`spec/esm-sources.md`](https://github.com/EarthSciML/EarthSciIO/blob/v0.3.0/spec/esm-sources.md).
See [`CHANGELOG.md`](https://github.com/EarthSciML/EarthSciIO/blob/v0.3.0/CHANGELOG.md#v030)
for the full list.

- **esm URL templates (§1):** `expand_esm_template` expands `{date:<format>}`
  and custom substitutions such as `{sector}` identically in every track, and a
  provider takes an esm template as its URL, with mirrors expanded at the same
  anchor and tried in order. Julia gains mirror failover in `fetch_blob` and
  `Provider`.
- **Calendar cadences (§2):** frequencies and file periods are
  `CalendarPeriod`s read from ISO 8601 durations, so `P1M` and `P1Y` sources
  land on real month and year boundaries instead of a mean-length month. Julia
  gains a time-varying `Provider(cache, url; format, temporal, window)`.
- **Providers from esm entries (§3):** Python `provider_from_esm`, Julia
  `provider_from_esm` and Rust `DataSource::from_esm` read the reader, URL
  template, mirrors, calendar block and reader options from an entry. Errors
  carry `esm_source_*` codes and the source's name.
- **Records by the file's own time axis (§2.5):** Julia and Rust now do what
  Python did, so files with missing or off-cadence records are read right.
  `decode_time_axis` exposes the CF decode in every track.
- **New readers:** `json` in every track, and `csv` in Rust.

### Breaking changes

- **Rust:** `SourceTemporal.frequency` and `.file_period` are `CalendarPeriod`
  values instead of `time::Duration`. `SourceTemporal::new` still accepts a
  `Duration`; one that is not a positive whole number of seconds is refused by
  `Provider::new` with `esm_period_invalid`.
- **Julia:** the csv reader's `header_row` is now 0-based (default 0), as in
  Python and Rust. A caller passing `header_row = n` must now pass `n - 1`.
- **All tracks:** monthly and yearly cadences now follow the calendar, so a
  source with a `P1M` or `P1Y` period reads different (correct) records and
  times than before. A csv header with a repeated column name, or a
  `numeric_columns` entry that the header lacks, is now an error.
